Evidence Checked October 12, 2026

Landscape, October 2026

Mods shipped on October 1 in Claude Code 2.1.287. In the eleven days since, nine more releases have come out and most of them changed something a mod author touches. Community scanners now index about 3,500 public mods. This page covers what changed, which fixes matter if you write a guard, and how far to trust a catalog.

Provenance. Release lines are quoted from the GitHub release notes and were checked with gh release view on October 12. The event count comes from the type declarations bundled with 2.1.296. Catalog numbers come from each catalog's own README on October 12, and claims a catalog makes about its own testing are marked as self-reported. Our own experiments are on Field tests.

Fixes that matter if you write a guard

A guard is a mod that stops things: a tool.call hook that denies a command, a prompt.submit hook that drops a prompt. Each of these fixes closed a way past one.

  • 2.1.295: truncated nested input. A hook could be handed a deeply nested tool input that had been cut short, with no error, so a guard could pass content it never saw. If you tested a guard before 2.1.295 on large or deeply nested inputs, such as an MCP tool with a big JSON argument or a long multi-edit, test it again.
  • 2.1.296: Esc during prompt.submit. Pressing Esc or interrupting while a mod's prompt.submit hook ran could let the unchecked prompt through, end a headless session, or clear the typed prompt. The same fix covers settings UserPromptSubmit hooks.
  • 2.1.295: prompt.mention. This one is a new event rather than a fix. A file named after @ in a prompt is read without raising tool.call, so a secrets guard that hooks only tool.call never sees it. Hook both, and give the prompt.mention hook a .catch, because a guard there that fails is skipped and the file is read.
  • 2.1.290: .catch made visible. claude plugin validate now prints gating hook without .catch for each guard-shaped hook that would fail open. The reference calls this "a fact, never a warning." For a real guard, add .catch(($, e, next) => next.called ? next(e) : { deny: 'why' }). Also in 2.1.290: a hook with a .catch could be unloaded and its .catch skipped when it kept the hooks worker busy. That's fixed.
  • 2.1.289: compound commands on managed machines. A deny or ask rule on one part of a && b now holds over a user mod's approval.
  • 2.1.293: classic.* hooks during a worker restart. They were skipped. A mod that reloads its state in classic.SessionStart after /clear could miss the reload while this bug was live.

The pattern

Most guard bugs on this list weren't logic errors in the guard. The guard was never asked: the input was cut short, the file came in through another event, the hook was skipped during a restart, or the prompt got past during an interrupt. Write the guard to fail closed, hook every event the protected thing can arrive by, and re-run your tests after each Claude Code release. See Mods meet the cascade for a guard laid out that way.

sec-default grew on October 11

The public source in anthropics/claude-code/mods has had three commits since October 2. One, on October 7, fixed how the diff pane docks. The other two are bulk updates, on October 8 and October 11. The October 11 update changed only sec-default, and its README went from 188 to 270 lines. Compared row by row, the guard now also holds these events out of a user mod's reach (checked 10/12):

  • env.get and env.set, with a new idea of pinned variables. A variable that managed settings set in env, plus nine that move where policy and sign-in are read from (CLAUDE_CONFIG_DIR, CLAUDE_CODE_MANAGED_SETTINGS_PATH and others), can't be set or unset by a user mod.
  • prompt.attachment, session.append for rows the engine injects, and ui.log lines from an organization's own mods.
  • session.compact, entirely. A user mod's compaction hook doesn't run where the guard is seated. The guard is seated on any machine with managed settings, and for anyone signed in on a Team or Enterprise plan.

Its README is still the best worked example of a policy mod. It uses three moves and nothing else: continue past the user tier with next.to(e, 'append'), refuse by name, or pass. Its policy reads fail closed.

Before you install a mod from any catalog

A mod runs with your permissions and isn't sandboxed. It can read your files and secrets, approve tool calls and spend your usage. Clone it and run claude plugin validate ./the-mod. Read the hooks: and calls: lines, because static analysis lists every $ call the module can make, and Claude Code refuses to load a module whose calls it can't read. A catalog's access badge is that same validator output at scan time, so it can go stale once the author pushes.

Guard mods such as bash-guard, secret-shield or guardrails fail open unless they register .catch. They lower risk in permission-skipping modes. They don't remove it. validate on 2.1.290+ tells you which hooks lack a .catch.

What to watch

  • The release cadence. Ten releases between October 1 and October 9, most of them touching mods. Pin the Claude Code version you test against, and re-run claude plugin test on every upgrade. The 2.1.289 bug that kept installed mods from loading in the first session after an upgrade is a reminder that "it did nothing" can be the engine's fault.
  • Drawing beyond the terminal. The declarations still type mobile and vscode render surfaces that the docs don't list as drawing. In 2.1.296, mods draw only in the terminal and the Desktop Code tab.
  • sec-default's reach. It took five more events on October 11. If your mod rewrites compaction, environment variables or injected rows, test it on a managed machine or a Team plan, where the guard is seated.
  • Catalog consolidation. Two scanners, karanb192 and Singh-AP, now index roughly the same 3,500 public mods every day. Neither is official, and both rely on the validator's static analysis, which shows what a mod can call, not what it does.
  • Unused API. On 10/8 no official sample used $.model, $.agent, $.audio or $.tool. Those are the parts of the API with the fewest worked examples, and probably where the next surprises are.
